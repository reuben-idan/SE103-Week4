What a pull request asks teammates to do:
A pull request asks teammates to review a set of commits on a branch and decide whether those changes should be merged into another branch, usually main. They can read the description, inspect the diff, and leave comments before the code becomes part of the shared history. Merging is the step that accepts the work after that review.

Why branches and pull requests are used together:
A branch holds the work in isolation, and a pull request is the conversation and merge request for that branch. Without a branch, there is nothing separate to review. Without a pull request, the branch might be merged with no description, no discussion, and no clear record of what landed on main.
